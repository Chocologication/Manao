# POC4：浏览器开发工作台设计与实施计划

## 1. 目的

验证真实 Kubernetes 开发工作台的最小闭环：固定测试用户创建私有 Maven 项目，在浏览器中安全地查看和编辑其 PVC 中的文件，运行 `mvn clean test`，实时查看容器日志，并在活动 Job 中使用交互式 Shell。

POC 通过的依据不是静态界面，而是完整真实链路能够稳定运行，并对跨用户访问、文件路径和 Job 生命周期施加明确约束。

## 2. 已确认边界

### 包含

- React + TypeScript + Vite 工作台。
- 固定测试账号登录和短期 JWT。
- 私有项目创建、最小 Java 17 Maven 模板、每项目 10 GiB RWX PVC。
- 目录树、文本文件读取/保存、文件与目录创建、重命名、删除确认。
- Monaco 编辑器、多标签、显式保存、文件大小分级处理。
- 真实 Kubernetes Job：`mvn clean test`、实时日志、停止、30 分钟超时、资源限制。
- 活动 Maven Job 容器的交互式 Shell，以及命令审计。
- MySQL 持久化项目、运行、滚动日志和审计；后端重启恢复运行锁。
- 自动化测试和真实集群演示。

### 不包含

- 移动端、Git 状态、上传、拖拽、批量操作、项目删除、多人协同编辑。
- AI 的上下文、CRUD、补丁确认和写入流程。
- 生产级网络隔离、出网白名单、计费、项目归档和可恢复删除。
- 同一项目在多个浏览器标签页的并发编辑冲突处理。

## 3. 架构

```text
浏览器
  | HTTPS / WebSocket，携带 JWT
  v
主后端（认证、项目授权、MySQL、Job 控制、日志/终端桥接）
  | 集群内文件 API，服务端项目所有权校验已完成
  v
项目工作区 Pod（仅内网、无 K8s 权限、PVC 读写挂载）
  |
  v
项目 RWX PVC <---------------- Maven Job（PVC 读写挂载）
                                      |
                                      +-- Pod 日志与 PTY exec
```

### 3.1 组件职责

| 组件 | 职责 | 不负责 |
|---|---|---|
| React 前端 | 登录、项目列表、文件树、Monaco、运行状态、日志和终端 UI | 直接访问 PVC、直接操作 K8s |
| 主后端 | JWT 验证、项目授权、MySQL 状态、PVC/Pod/Job 生命周期、WebSocket 桥接 | 直接暴露所有项目文件 |
| 工作区 Pod | 仅处理其 PVC 的受控文件 API | 对外认证、K8s API、执行用户命令 |
| Maven Job | 执行 `mvn clean test`、输出日志、提供运行期 Shell | 访问其他项目或 K8s API |
| MySQL | 项目、资源映射、运行、日志片段、终端审计 | 项目文件正文 |
| RWX PVC | 项目文件权威副本 | 日志索引、权限决策 |

### 3.2 项目创建流程

1. 已认证用户提交显示名称。
2. 主后端检查该用户项目数小于 3，并写入项目草稿记录。
3. 后端在专用命名空间创建带 `ownerUserId` 与 `projectId` 标签的 10 GiB PVC 和工作区 Pod。
4. 工作区 Pod 就绪后，主后端通过内部 API 写入 Java 17 Maven 模板。
5. 后端在 MySQL 标记项目可用；前端进入文件树和编辑器。

创建失败时记录失败原因并清理本次创建的资源；POC 不提供用户侧项目删除入口。

## 4. 文件模型

### 4.1 保存和路径安全

- 前端只发送相对路径与内容；项目和用户身份由 JWT 确定。
- 工作区 Pod 对每个路径执行规范化，拒绝绝对路径、`..`、符号链接逃逸与项目根目录外访问。
- 用户只能通过保存按钮或 `Ctrl+S` 写入；运行按钮在存在未保存模型时不可用。
- 删除必须二次确认，且为不可恢复删除。

### 4.2 文件大小策略

| 文件类型 | 上限 | 行为 |
|---|---:|---|
| 普通代码文本 | 20 MiB | Monaco 完整编辑 |
| Markdown，20 MiB 以下 | 20 MiB | Monaco 编辑，无实时预览 |
| Markdown，20–50 MiB | 50 MiB | 纯文本降级，关闭 Markdown 增强 |
| 二进制或超过上限 | 不加载 | 只显示元信息与下载入口 |

隐藏文件默认可见。此决定仅适用于测试阶段；项目 PVC 中不得存放平台密钥或服务账号凭据。

## 5. 运行状态机

```text
可编辑
  -> 启动中（检查已保存、创建 runId 与 Job）
  -> 运行中（编辑与 AI 锁定；日志与 Shell 可用）
  -> 结束中（停止、超时或完成，等待 K8s 确认）
  -> 强制重载工作区
  -> 可编辑
```

- 每项目只有一个活动 Job。
- Job 命令固定为 `mvn clean test`，镜像固定 Java 17 + Maven 3.9。
- 最长运行 30 分钟；用户可主动终止。只有后端确认 Job 已终止或达到明确失败状态后才解锁。
- 运行容器和 Shell 都能读写项目 PVC。Maven 产物与 Shell 副作用会保留在工作区；结束后的强制重载是避免前端缓存失真的必要补偿，不提供运行快照或源码可复现性。
- Job 的请求与限制值必须在 `8 CPU / 16 GiB / 10 GiB` 硬上限内。

## 6. 日志与终端

### 6.1 日志

- 后端从 Pod 日志读取事件，持久化后再通过 WebSocket 推送。
- 每次运行最多保留最近 5 MiB；淘汰最早片段，记录截断状态和淘汰字节数。
- 浏览器刷新或断线后先读取持久化窗口，再订阅实时流。
- 开始下一次运行时前端切换到新运行；旧运行日志和元数据在 MySQL 保留 7 天。
- 后端重启后依据 MySQL 与 K8s 标签恢复活动运行、锁和订阅；恢复中不允许编辑。

### 6.2 终端

- 仅对当前活动 Maven Job 的运行中应用容器开放，不允许进入工作区 Pod。
- 使用 WebSocket 双向桥接 Kubernetes PTY exec。
- 刷新、断线和页面关闭立即结束旧 exec；用户可在同一 Job 未结束时重新打开新会话。
- 审计执行者、命令、开始/结束时间、退出码；Shell 输出单独显示，不能混入 Pod 日志。

## 7. 安全与隔离

- 固定测试账号的密码仅由服务器环境变量提供，浏览器仅持有短期 JWT。
- 每个 K8s PVC、工作区 Pod 与 Job 均带受控的项目和所有者标签；后端先校验 JWT 所属关系，再接受任何资源引用。
- 运行 Job 使用无 RBAC 的专用 ServiceAccount，设置 `automountServiceAccountToken: false`。
- POC 允许任意出网，不能宣称为生产级沙箱。任意 Shell 与读写工作区是经确认的测试阶段取舍。
- 工作区 Pod 不配置外部 Service/Ingress，不授予 K8s API 权限；浏览器不得绕过主后端访问它。

## 8. MySQL 持久化模型

至少维护以下逻辑实体：

- `test_user`：固定测试用户的标识与密码哈希。
- `project`：所有者、显示名、PVC 名称、工作区 Pod 名称、状态、创建时间。
- `run`：项目、Job 名称、状态、资源配置、开始/结束时间、终止原因、日志截断信息。
- `run_log_chunk`：运行日志的顺序片段、字节数与时间；按最近 5 MiB 滚动淘汰。
- `terminal_audit`：运行、用户、命令、开始/结束时间、退出码。

日志与运行记录在结束后保留 7 天，使用定时任务删除到期数据。

## 9. 实施顺序

1. 建立 POC4 目录、React + TypeScript + Vite 前端和 Spring Boot 后端骨架；配置 MySQL、JWT 与固定测试账号。
2. 实现项目元数据、每用户 3 项目限制、PVC 与工作区 Pod 创建、Maven 模板初始化和失败回收。
3. 实现主后端到工作区 Pod 的内部文件代理，以及目录树、文件 CRUD、路径安全和大小限制。
4. 接入 Monaco，完成多标签、显式保存、未保存阻止运行与运行期锁定。
5. 创建受资源限制的 Maven Job，接入 `mvn clean test`、停止、30 分钟超时和 Job 状态恢复。
6. 实现持久化日志窗口、WebSocket 实时推送、刷新补拉和 7 天清理。
7. 接入 xterm.js 与 Kubernetes PTY exec，完成断线关闭和终端审计。
8. 完成端到端演示、授权和路径安全等自动化测试，并验证后端重启恢复。

## 10. 通过标准

1. 两个不同测试用户只能看到并操作自己的项目；伪造项目、PVC、Pod 或路径均被拒绝。
2. 用户创建项目后能立即编辑模板，保存后文件树与 PVC 内容一致。
3. 有未保存文件时不能启动；运行中不能编辑；Job 完成或终止后前端强制重载并显示容器写入的变化。
4. `mvn clean test` 在真实 Job 中执行，日志实时出现；超时、手动停止和失败均会正确解锁。
5. 日志超过 5 MiB 后仍持续显示最新内容，刷新或断线后能恢复最近窗口；旧记录在 7 天后被清理。
6. 用户能在活动 Maven Job 容器中使用交互式 Shell；断线后会话关闭，命令审计可查询。
7. 后端在 Job 运行中重启后，项目保持锁定并恢复运行状态与日志订阅。

## 11. 后续单独评审的事项

- AI 读取明确选中文件与运行记录、生成建议或补丁、用户确认后的文件 CRUD。
- 同项目多标签编辑冲突、版本快照、Git 集成和项目归档。
- 生产级网络策略、出网白名单、恶意代码沙箱、存储回收与计费。
