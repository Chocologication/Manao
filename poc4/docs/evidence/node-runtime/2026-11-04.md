# Node.js 运行环境本地验收（2026-11-04）

本轮新增 JavaScript / TypeScript 控制台和 Web 服务模板，完成前后端合同、源码初始化、Node 运行器、AI 构建选择及本地 mock 交互。相关本地验证 PASS；Docker 镜像构建、Kubernetes 实际运行和真实模型调用 NOT_RUN。实现分支为 `codex/ai-conversation-redesign`，未推送仓库、未部署，用户人工验收尚未进行。

## 实现范围

| 模板 | 类型 | 默认执行 |
| --- | --- | --- |
| `node-javascript-console` | TASK | JavaScript 编译检查后运行 |
| `node-javascript-web` | SERVICE | JavaScript HTTP 服务，默认端口 3000 |
| `node-typescript-console` | TASK | TypeScript 编译到 `dist/` 后运行 |
| `node-typescript-web` | SERVICE | TypeScript 编译后启动 HTTP 服务，默认端口 3000 |

- 固定工具链：Node.js 24 LTS（镜像版本 24.15.0）、pnpm 10.33.0；TypeScript 5.9.3、`@types/node` 24.10.0。四套模板均包含真实生成的锁文件和默认测试。
- 运行器安装锁定依赖、构建、启动；保留实际退出码，处理停止和临时副本清理。依赖安装使用 `--ignore-scripts`，项目私有缓存复用已有 workspace PVC。
- Web 模板支持 `/health/ready`、404，以及按所选依赖检查 MySQL / Redis。保持既有公网端口范围、启动预算和首次就绪后两小时寿命合同。
- Node AI 构建按服务端保存的模板选择运行器，支持 `compile`、`test`、`package`；兼容 Node JUnit 报告，不把缺失报告推断为测试通过。本轮未调整 Python AI 构建的既有执行方式。
- 前端新增模板选择、Node 运行状态和页脚信息；workspace-agent 与 mock 补充 JavaScript、TypeScript、JSON、YAML 的文件语言识别。Node mock 项目文件从后端模板生成，保持 JSON 数据与浏览器源码边界。
- Node 镜像缺失时明确返回 `NODE_RUNTIME_NOT_CONFIGURED`。部署配置要求 `MANAO_NODE_RUNNER_IMAGE` 使用带 `@sha256:` 的不可变引用。
