## 实际工作台结果

| 语言 | 本地自动触发到灰字 | 云端自动触发到灰字 | 两轮共同断言 |

每个最终轮次各观测到 6 次码瑙 FIM 接口请求，包含接受后的 follow-up；这不是本会话全部实验请求的计数。时间包含 onIdle 的 400 ms 等待，不给出可靠 p95。请求模型为已核对运行配置及请求代码的 `deepseek-flash`；产品接口不透传上游响应的 model 元信息，因此没有独立确认该响应字段。

云端浏览器只使用 `http://1.12.245.235:30080`，本地 Vite、测试 nginx 与 Java 后端关闭，4173/18080 无监听。收尾终止 3 个本次项目残留的 kubectl port-forward 后，最后再次执行三语言公网真实验收 PASS，表中云端时间取该轮；前一轮结果同时保存在 JSON 的 cloudInitial。已有操作者管理 SSH/API 隧道保留用于发布与状态核对；它不是浏览器应用代理或运行依赖。未停止其他聊天/用户的既有管理进程。

最终本地与云端分别出现 4 / 5 条非阻断 `Canceled`。source map 对齐同一前端镜像，只单列已在历史探针出现的两条路径：`async.js:300 → cancellation.js:45 → runOnChange.js:45`，及 `Delayer.cancel async.js:251 → WordHighlighter.dispose wordHighlighter.js:652`。新增异常数均为 0；“页面异常为零”继续 FAILED，根因/修复 NOT_REVERIFIED，生产错误处理不变。Python 多行换行修复继续 WAIVED_BY_USER，历史 FAILED 未改写。

## 本轮失败与修正边界

- 私有 `.env` 外层引号被加载脚本保留，造成最初的登录 401 和 FIM 503；修正私人配置解析后通过，未改功能代码。
- 初版真实测试使用硬导航，触发现有内存会话清理；改为实际项目卡片的 SPA 导航。
- 本地 Docker host 的 IPv6 不可达；本地测试 nginx 改用实测 DNS A 记录。候选前端启用 AI 面板而本地后端关闭 authority 接口会触发现有只读保护，对齐本地配置后再等待实际 Monaco 可写；未绕过写锁。
- 云端首轮的异常诊断脚本拉取 source map 连接超时，使测试失败；最终从已核对 digest 的同一前端镜像提取 maps 解析。功能代码与部署镜像不变，不把失败轮次改写为通过。
